## 분석

### Get (Rust 1.57배)

측정 구간과 요청은 같다. .NET `Utility.GetBodySplit`은 본문을 용량 없는 `MemoryStream`에 복사해 1MiB마다 버퍼 재할당·LOH GC가 생긴다(RSS 최대 589MiB). 런타임 처리 비용 차이이며 원본 동작이라 그대로 둔다.

### Put (Rust 0.92, 세 회차 모두 5~11% 낮음)

20초 Put을 `perf stat`/`perf record`로 비교했다.

| | 쓰기 건수(20초) | task-clock | user / sys | context switch |
| --- | --- | --- | --- | --- |
| .NET | 9,401 | 59.5 s | 33.8 / 25.9 s | 547K |
| Rust(mallocng) | 8,257 | 50.9 s | 17.0 / 34.8 s | 1,039K |
| Rust(mimalloc, 시험 빌드) | 8,372 | 25.9 s | 16.5 / 10.6 s | 382K |

- mallocng 빌드의 핫스팟: `futex_wake ← __unlock` 스핀락, `__libc_malloc_impl`, 페이지 폴트, munmap IPI. musl 할당기의 전역 락 경합.
- mimalloc으로 바꾸면 CPU가 절반이 되지만 처리량은 거의 같다. 즉 CPU는 병목이 아니고, 요청당 지연 차이가 남는다.
- 남은 후보: hyper `HttpConnector`의 TCP_NODELAY 기본값(false, .NET SocketsHttpHandler는 true)과 요청 쓰기 방식. 아직 확인하지 않았다.
